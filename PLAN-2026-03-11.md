## Issues (ordered by priority)

### Issue 1: Onboarding allows multi-select (should be single) + CEO role doesn't fit
**Status:** Bug + UX  
**File:** `pages/onboarding-unified.html`  
**Root cause:** `selectedRoleIds` is an array, `toggleRole()` adds/removes, UI shows "X/Y selected" counter  
**Fix:**
- Change to single-select: `selectedRoleIds` → `selectedRoleId` (string, not array)
- Replace CEO with a 3rd PA variant (e.g., "Strategic Advisor" — analytical, data-driven)
- All 3 roles are personal assistant flavors: Friendly PA, Ruthless Mentor, Strategic Advisor
- Add `server/templates/roles/strategic-advisor.json`, remove `ceo.json`
**Test:** Open onboarding → click one role → click another → first deselects → submit → only 1 agent created

### Issue 2: No auto-redirect to Link Channel after onboarding
**Status:** Bug  
**Files:** `server/controllers/onboardingOneShot.js`, `server/controllers/onboardingUnified.js`  
**Root cause:** Unified returns `redirect: '/dashboard'`, one-shot returns `POST_ONBOARD_URL` (probably `/dashboard` too)  
**Fix:** Change redirect to `/link` (the link-channel page) so user immediately connects their messaging channel  
**Test:** Complete onboarding → auto-redirected to link-channel page

### Issue 3: No intro message from Chef on linked channel
**Status:** Missing feature  
**Files:** `server/controllers/channels.js` (saveChannelLink), entrypoint.sh (gateway config)  
**Root cause:** After channel link, no code sends an introductory message via OpenClaw gateway  
**Fix:** After `saveChannelLink()` succeeds, call OpenClaw gateway API to send intro message through the linked channel. The intro message text comes from the agent's SOUL.md or the role template's `introMessage` field.  
**Dependencies:** Issue 5 (Chef must be working first)  
**Test:** Link Signal → receive "Hi, I'm Chef..." message within 10 seconds

### Issue 4: No chat inside Chef's dashboard
**Status:** Bug (component exists, not wired)  
**Files:** `src/components/Chat/ChatPage.jsx`, `src/components/Layout.jsx`, `server/routes.js`  
**Root cause:** 
  - Chat component exists but not in navItems array
  - Chat backend endpoints (`/api/chat/session`, `/api/chat/send`) not registered in routes.js
  - No chat controller exists in server/controllers/
**Fix:**
  a. Add 'chat' to navItems in Layout.jsx (with MessageSquare icon)
  b. Create `server/controllers/chat.js` — proxy to OpenClaw gateway HTTP API
  c. Wire `/api/chat/session` (POST) and `/api/chat/send` (POST) in routes.js
  d. Add 'chat' page import in App.jsx
**Test:** Click Chat in sidebar → see chat UI → send message → get response from Chef

### Issue 5: Chef not responding over linked channel
**Status:** Critical bug  
**Root cause (candidates):**
  a. OpenClaw gateway not receiving messages from channel provider (Signal/WhatsApp config issue)
  b. Gateway agent config mismatch — agent ID in openclaw.json doesn't match channel config
  c. Provider API keys not loaded (OpenRouter key missing or expired)
  d. Channel dmPolicy blocking messages
**Diagnosis steps:**
  1. Check gateway logs: `docker logs <container> 2>&1 | grep -i 'signal\|message\|error'`
  2. Check agent config: `cat /root/.openclaw/openclaw.json`
  3. Check provider keys loaded: `cat /root/.openclaw/provider-keys.json`
  4. Check channel config: API call to board's `/api/channels`
  5. Test gateway HTTP directly: `curl http://localhost:18789/api/health`
**Fix:** Depends on diagnosis — likely config mismatch or missing channel setup  
**Test:** Send message on Signal → get reply from Chef within 30 seconds

### Issue 6: Chef not picking up Paperclip tasks
**Status:** Missing integration  
**Root cause:** There is NO integration between Paperclip's task system and OpenClaw gateway. Paperclip manages tasks in its SQLite DB. OpenClaw manages chat. They don't talk to each other.  
**Fix options:**
  a. **Polling approach:** Cron job in OpenClaw that polls Paperclip `/api/tasks` for assigned tasks and processes them
  b. **Webhook approach:** Add webhook to Paperclip that notifies OpenClaw when a task is assigned
  c. **Board middleware:** wisechef-board acts as bridge — when task is created/assigned, board server calls OpenClaw gateway API
**Recommended:** Option (c) — add a task webhook in board's task controller that sends to gateway  
**Test:** Create task in Paperclip → assign to Chef → task status changes to "in progress" → work appears

### Issue 7: Paperclip "new issue" popup doesn't close after creation
**Status:** Bug in Paperclip SPA  
**File:** `enterprise-dist/assets/index-DrB-XHld.js` (compiled)  
**Root cause:** Modal doesn't close on successful POST. This is in the compiled Paperclip bundle.  
**Fix options:**
  a. Patch the compiled JS (fragile, find the modal close handler)
  b. Rebuild Paperclip from source (`wisechef-enterprise-panel` repo, branch `stabilization/2603`)
  c. Add a CSS/JS injection via enterprise-mount that auto-closes modals on success
**Recommended:** Option (b) if Paperclip source builds. Option (c) as quick workaround.  
**Test:** Create issue → popup closes automatically → only 1 issue created

## Testing Strategy

### Unit Tests (per issue)
Each fix gets a test in `test/` before deployment:
- `test/onboarding.test.js` — single select, redirect, role templates
- `test/chat-api.test.js` — session creation, message send/receive
- `test/task-bridge.test.js` — task creation → agent notification
- `test/channel-link.test.js` — link + intro message

### Integration Test
`test/e2e-customer-journey.js`:
1. Boot fresh container from `:latest`
2. Hit onboarding → select PA role → verify single selection
3. Verify redirect to /link
4. Link test channel
5. Verify intro message received
6. Send chat message via dashboard → get response
7. Send message via channel → get response
8. Create Paperclip task → verify agent picks it up
9. Verify no Paperclip/Random-cmp branding

### Run Before Each Image Bake
```bash
# From docker host, against test container:
docker exec wisechef-test npm test
# OR from local:
node test/e2e-customer-journey.js --host <test-container-url>
```
